# AGENTS.md

## Что это

RitmDojo, ритм-тренажёр для гитары. Один статический сайт без сборки и зависимостей:
разметка, стили и скрипт лежат в `index.html`, голосовые сэмплы — в `voice/`.
Есть PWA-обвязка (`manifest.json`, `sw.js`, иконки) для установки и офлайн-работы.
Публикуется как GitHub Pages из корня репозитория.

## Быстрый старт

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

Открывать через `file://` нельзя: не зарегистрируется service worker, а микрофон и
`AudioWorklet` требуют secure context (`localhost` или https).

Сборки и линтера нет. `package.json` содержит только dev-зависимость
`@playwright/test`; на работу самого сайта она не влияет.

## Тесты

```bash
npm install
npx playwright install chromium   # если браузера ещё нет в кеше
npm test                          # весь suite, ~40 с
npm run test:headed               # с видимым браузером
npm run test:report               # HTML-отчёт после падения
```

Playwright сам поднимает `python3 -m http.server 4173` через `webServer` в
`playwright.config.js`, отдельно запускать сервер не нужно. Если порт 4173 занят,
`reuseExistingServer` переиспользует его локально (но не в CI).

Устройство тестов:

- `tests/helpers.js`: `boot(page, state)` (состояние кладётся через
  `addInitScript` один раз, чтобы пережить `reload`), ожидание голоса, чтение
  `opt`/`localStorage`, `openTab(page, 'play'|'score'|'settings')`, открытие
  `<details>`.
- `tests/boot.spec.js`, `navigation.spec.js`, `keyboard.spec.js`,
  `playback.spec.js`, `settings.spec.js`, `voice.spec.js`, `game.spec.js`,
  `pwa.spec.js`, `tabs.spec.js`, `records.spec.js`, `appearance.spec.js`:
  по доменам поведения.
- Шапка и подсказки проверяются в `tabs.spec.js`: порядок «шестерёнка → ? →
  логотип», пиксельные `rect` у `#wm` и `#bhelp`, переключение `#vhelp`.
- Таблица рекордов проверяется в `records.spec.js`: пустое состояние, сортировка,
  запись `opt.rec` через `result()` и защита рекорда от слабого повтора.
- Настройки и результат живут на скрытых вкладках, поэтому тесты, которые
  нажимают `#oloop`, `#ogm`, `#bcal` или проверяют `#rt`/`#hst`, сначала вызывают
  `openTab()` (кроме проверок текста/значений у скрытых элементов).
- Живой HUD (`#hud`, `#cv`, `#fb`) теперь на «Игре», поэтому проверки канваса
  идут без переключения на «Счёт»: скрытый канвас имеет нулевую ширину.
- Голос грузится из `voice/*.mp3`; тесты проверяют файлы через `request`, а
  `waitVoice()` ждёт декодирования всех пяти слов.
- В `playwright.config.js` по умолчанию `serviceWorkers: 'block'`, иначе кеш
  мешает изоляции; `pwa.spec.js` включает их через `test.use`.
- Микрофон подменяется фейковым устройством Chromium с файлом
  `tests/fixtures/silence.wav`; это даёт детерминированные нулевые атаки.
  Реальную акустику и задержку оборудования тесты не проверяют.
- Внутренние функции (`B`, `opt`, `g`, `e`, `onset`, `result`, `start`, ...)
  доступны из `page.evaluate`, потому что скрипт классический и живёт в
  глобальной области. Переименование этих сущностей ломает тесты.
- `page.clock` используется для калибровки: `fastForward(12000)` проходит
  `setTimeout` на 11,5 с без реального ожидания.

```bash
python3 - <<'EOF' > /tmp/ritmdojo-app.js
import re
s = open('index.html').read()
print(re.search(r'<script id="app">(.*?)</script>', s, re.S).group(1))
EOF
node --check /tmp/ritmdojo-app.js
```

Целостность голосовых файлов:

```bash
python3 - <<'EOF'
from pathlib import Path
for p in sorted(Path('voice').glob('*.mp3')):
    d = p.read_bytes()
    print(p, len(d), d[:3])
EOF
```

Должно быть пять файлов (`raz`, `dva`, `tri`, `chetyre`, `i`) с началом `ID3`.

После правки `index.html` обязательно поднять `VERSION` в `sw.js`. Иначе браузер
продолжит отдавать старую версию из кеша (стратегия cache-first).

## Архитектура `index.html`

Скрипт `#app` выполняется в глобальной области, без модулей и без фреймворка.
Разметка статическая, все элементы ищутся по `id` через `$ = s => document.getElementById(s)`.
Обработчики навешиваются в конце скрипта, а не атрибутами `onclick` в HTML.

### Экраны и вкладки

Разметка разделена на четыре `section.view`: `#vplay` (урок, транспорт и живой
результат), `#vscore` (итог, тайминг и таблица рекордов), `#vset` (все настройки)
и `#vhelp` (подсказки). `showView(v)` переключает атрибут `hidden`, класс `.on` и
`aria-selected` у `#tplay`/`#tscore`, а также `aria-pressed` у шестерёнки `#bset`
и кнопки `#bhelp`.

Шапка: слева крайней стоит шестерёнка `#bset`, сразу за ней кнопка подсказок
`#bhelp` с пиксельным знаком вопроса, затем `.brand` (логотип `#logo` и название
`h1`), справа — вкладки. Шестерёнка и «?» работают переключателями: повторное
нажатие возвращает на игру. По умолчанию открыта игра; выбранная вкладка не
сохраняется.

Название `h1` — не текст, а пиксельный SVG `#wm`: глифы 5×7 лежат в объекте `PF`,
функция `pxs()` превращает строки из `0/1/2` в `rect` (символ `2` — красный
акцент, точка у «i» и «j»). Для доступности рядом стоит `<span class="sr">`. При
правке глифов следите, чтобы у всех строк одной буквы была одинаковая ширина.

Логотип `#logo` — inline SVG 16×16 с `shape-rendering="crispEdges"`: корпус
метронома, маятник `#lneedle` и нога `#lfoot`. `foot(f)` двигает маятник по
пикселям влево-вправо и приподнимает ногу на «и», поэтому отдельной картинки
ноги на игровом экране больше нет. Иконки PWA — заливной вариант того же
метронома; при смене рисунка их нужно перегенерировать в размерах 192, 512,
maskable 512 и 180.

### Данные упражнений

```js
const H = .5, T = 1/3, S = .25, X = 1/6;       // длительность шага в долях
const EX = [{ t: 'Четверти', l: [60, 80, 100], p: [['Все четверти', g('Xxxx', 1)], ...] }, ...];
const B = [];                                    // плоский список блоков
EX.forEach((x, xi) => x.p.forEach((p, pi) => x.l.forEach((v, ti) =>
  B.push({ xi, pi, ti, bpm: v }))));
```

- `EX` — темы. `t` название, `l` три темпа (чипы), `p` пары «название, события».
- Событие это `[начало в долях от 0 до 4, акцент, длительность в долях]`.
- `g(pattern, step)` строит события из строки: `X` акцентированная нота, любой
  другой символ кроме `.` обычная нота, `.` пауза. Пробелы игнорируются.
  Длительность каждого события равна `step`, включая последнее. Поэтому у рисунка,
  который заполняет такт целиком, последняя нота тоже заканчивается ровно на 4
  долях, как и у `e()`. Если строка короче такта или кончается паузой, нота
  остаётся длиной `step`: тянуть её до конца такта нельзя, иначе пауза в конце
  рисунка исчезнет.
- `e(offsets, off)` строит события из абсолютных смещений: длительность считается
  до следующего события, последнее тянется до конца такта (4 доли). Второй аргумент
  `off` переключает трактовку акцента: без него акцентируются доли на сильной позиции
  (`s % 1 == 0`), с `1` — синкопы (`s % 1 != 0`).
- `B` упорядочен по теме, затем по рисунку, затем по темпу. Индекс `B` это
  идентификатор блока: он хранится в сохранениях, используется в прогрессе,
  клавишах и статистике. Перестановка или вставка блоков ломает сохранённые звёзды.

Поиск блока: `find(xi, pi, ti)` (для неизвестной комбинации возвращает `-1`).
Навигация: `go(i)` (с закольцовыванием по всему `B`), `pat(±1)` (следующий
рисунок внутри текущего темпа 0). Селекторы темы, рисунка, темпа и клавиши
`1`–`8` ходят через `jump(xi, pi, ti)`: он молча пропускает `-1`, иначе
несуществующий блок закольцевался бы в последний.

### Планировщик воспроизведения

- `start(countIn)` создаёт/возобновляет `AudioContext`, сбрасывает состояние игры,
  ставит `sc = cur` (курсор планировщика), `k = countIn ? -1 : 0` и запускает
  `setInterval(tick, 40)`.
- `sched()` планирует один такт вперёд: метроном (`click`), голос (`say`), ноты
  рисунка (`note`), события для игры (`xq`) и бары для отрисовки (`bh`).
  Такт всегда 4/4, длительность `4 * spb`, где `spb = 60 / bpm`.
- `tick()` досрочно планирует всё, что попадает в окно `max(.4, 360 / bpm)` секунд.
- `frame()` это `requestAnimationFrame`-цикл. Он читает очередь `q`, двигает
  визуальный курсор `cur`, обновляет прогресс, фазу, ногу, полосу рисунка и
  вызывает `gameTick` в режиме игры. Визуальное состояние всегда идёт за очередью
  уже запланированных тактов, а не за `sc`.
- Такты блока: `k < 0` счёт перед стартом, `0..L-1` «Слушай», `L..L+P-1` «Играй»,
  `L+P` итоговый такт в режиме игры. Число тактов и `bdur()` учитывают
  дополнительный такт `opt.GM`.
- Счёт бывает на один или два такта (`opt.count` + `opt.CB`), поэтому `start()`
  ставит `k = -opt.CB`. В первом такте двухтактного счёта звучат только «раз»
  (доля 1) и «два» (доля 3), во втором — «раз, два, три, четыре» с «и» на слабых
  долях. Визуально `#bars` показывает «счёт 1 из 2» и «счёт 2 из 2».
- `stop()` останавливает таймер, глушит звук и пересоздаёт выход (`kill()`).

Темп: `bpmOf(i)` берёт темп блока плюс глобальный `shift`, зажатый в диапазоне
30–240. `shift` меняется кнопками ±5 и клавишами `-`/`=`, хранится отдельно от `opt`.

### Режим игры

- Вход с микрофона включается чекбоксом «Игра включена»; `micOn()` запрашивает
  `getUserMedia` с выключенными echoCancellation/noiseSuppression/autoGainControl.
- Детектор атак `class Det` сериализуется через `Det.toString()` в исходник
  `AudioWorklet` (`WK`, строка около 209). Поэтому `Det` обязан быть
  самодостаточным: никаких ссылок на внешние переменные, константы или методы.
  При недоступности `AudioWorklet` используется `createScriptProcessor` и тот же `Det`.
- `onset(t)` сопоставляет найденную атаку с ближайшей ожидаемой нотой (окно 130 мс),
  вычитая задержку `lat()`. Оценка: `≤ 45 мс` идеально, `≤ 90 мс` хорошо,
  иначе рано/поздно; пропущенная ожидаемая нота даёт «Мимо», а лишняя атака
  попадает в `pv` с `r = 'x'` и рисуется красным ромбом.
- Точность: `(p + .6*g - .3*x) / n`. Уровень пройден при 60 %, звёзды при 75 % и
  90 %. Множитель `1 + min(3, combo >> 3)`. Рекорд и звёзды хранятся в `opt`.
- Живой результат (`#hud`) живёт на вкладке «Игра»: счёт, множитель и серия,
  точность, восемь пиксельных делений `#cbar` до следующего множителя, канвас
  `#cv` с ожидаемыми и сыгранными нотами и `#fb` с оценкой. На вкладке «Счёт»
  остались итог, тайминг `#tm` с гистограммой `#hg` и таблица рекордов.
- `result(bi)` вызывается на итоговом такте: считает точность и звёзды, копит
  `score`, обновляет `opt.best` и `opt.rec[bi] = { a, st, bpm }` (только если
  точность выше прежней; звёзды не понижаются) и вызывает `recUpd()`.
- `recUpd()` строит `#rt`: лучшие 12 блоков по звёздам, затем по точности, затем
  по темпу; показывает номер урока, тему с рисунком, темп, точность и звёзды.
- `endBlock()` после итогового такта либо переходит к следующему блоку, либо
  повторяет текущий, если уровень не пройден.

### Голос

- Пять MP3 лежат в `voice/` под ASCII-именами: `raz.mp3`, `dva.mp3`, `tri.mp3`,
  `chetyre.mp3`, `i.mp3`. Карта `VF` сопоставляет русские слова файлам, `loadE()`
  грузит их через `fetch` по относительным ссылкам и декодирует в `AudioBuffer`,
  обрезает ведущую тишину и считает `PC` — положение ударной гласной по
  спектрограмме. Автосмещение `opt.O[слово] = -PC` выставляется только если для
  слова ещё нет сохранённого значения, поэтому ручная подстройка не перетирается.
- Если загружены все пять слов, `say()` играет буферы; иначе используется
  `speechSynthesis` с русским голосом и поправкой `opt.D`. При ошибке загрузки
  (нет сети и нет кеша) слово просто остаётся незагруженным, страница не падает.
- Имена файлов продублированы в `VF` и в списке `SHELL` в `sw.js`: новый файл без
  записи в `SHELL` не попадёт в офлайн-кеш.
- `start()` задерживает старт на максимальное отрицательное смещение слова, чтобы
  ни одно слово не попало в прошлое.
- Хранилища голосов в IndexedDB больше нет: `db`, `putV` и `loadV` удалены.
  Сэмплы всегда берутся из `voice/`, офлайн обеспечивает service worker.

### Сохранения

- `localStorage['rt2']` = `{ cur, shift, opt }`. Читается один раз при старте,
  `opt` мержится через `Object.assign`: новые поля из сохранения переживают
  обновление, а неизвестные поля не удаляются.
- `opt` содержит: `loop`, `count`, `CB` (тактов счёта 1–2), `L` (тактов слушания 0–8),
  `P` (тактов игры 1–16), `V` (голос), `D` (задержка голоса, мс), `G` (громкость
  голоса, %), `N` (звук рисунка), `NP` (рисунок и в игре), `NG` (громкость
  рисунка, %), `GM` (игра), `S` (чувствительность 0–100), `CAL`/`CALD`
  (калибровка), `OUT`/`MIC` (устройства), `HI` (рекорд), `best` (звёзды по
  индексу блока), `rec` (лучшая точность, звёзды и темп по индексу блока),
  `O` (смещения слов, мс).
  В дефолтном литерале `opt.O` лежат латинские ключи `c/t/n/v`; реальные смещения
  пишутся по русским словам при `decodeV` и затем сохраняются.
- `best`, `rec` и `HI` привязаны к индексам `B`; при изменении `EX` старые
  рекорды становятся неверными. `hst` считает сумму звёзд из `B.length * 3`.
- Все обращения к `localStorage` обёрнуты в `try/catch` и молча игнорируют ошибки
  (приватный режим, запрет хранилища). Логов в консоли нет.

## Соглашения

- Интерфейс, комментарии и README на русском. Новые строки UI тоже на русском.
- Стиль кода: компактный ES2019+, одна-две строки на функцию, короткие имена
  (`$`, `g`, `e`, `B`, `EX`, `opt`), одинарные кавычки, точки с запятой.
  Не переформатировать файл целиком и не вводить prettier.
- Никаких внешних зависимостей, шрифтов и CDN: приложение должно работать офлайн.
- Новые элементы: `id` в разметке, доступ через `$('id')`, стили через переменные
  `--bg`, `--card`, `--fg`, `--mut`, `--line`, `--lis`, `--ok`, `--need`.
  Тёмная тема задаётся `prefers-color-scheme` и атрибутом `data-theme` на `:root`.
- Числовые настройки: добавляйте поле в литерал `opt` с дефолтом, синхронизацию
  элемента в блоке инициализации и `save()` в обработчике.
- Слои не смешивать: `sc`/`nextT`/`q` — планировщик, `cur` — UI, `gs`/`xq`/`nv`/`pv` —
  состояние текущего проигрывания.

## Подводные камни

1. **Service worker отдаёт кеш первым.** Изменили `index.html` — поднимите
   `VERSION` в `sw.js`. Новый статический файл нужно добавить в `SHELL`, иначе
   офлайн он не загрузится. `sw.js` намеренно не кешируется.
2. **Голос — внешние файлы.** Пять MP3 лежат в `voice/`, имена — часть контракта
   `VF`. Переименование требует правки `VF`, `SHELL` в `sw.js` и `tests/voice.spec.js`.
   Файлы должны начинаться с `ID3`; битый MP3 молча выпадает из набора, и голос
   переключается на браузерный.
3. **`Det` уезжает в worklet через `toString()`.** Любая внешняя ссылка внутри
   класса (константа, хелпер, `opt`) сломает детектор в worklet-режиме. В
   ScriptProcessor-режиме тот же класс работает в основном потоке, поэтому
   расхождение легко не заметить.
4. **Два курсора.** `sc` — что уже поставлено в очередь, `cur` — что сейчас на
   экране. Не используйте `sc` для отрисовки и не двигайте `cur` вручную во время
   проигрывания: `frame()` сам переключит блок на границе такта.
5. **Единицы — доли, не миллисекунды.** Все события и `drawStrip` работают в долях
   от 0 до 4. `drawStrip` подбирает сетку из фиксированного набора
   `[.5, 1/3, .25, 1/6, .125]`; событие со смещением, не кратным 1/8, отрисуется
   по сетке 1/8 и будет выглядеть неверно. Новые рисунки держите в этих долях.
6. **Порядок `B` — часть контракта.** Он влияет на сохранённые звёзды, прогресс,
   номера блоков в HUD и клавиши. Вставляйте новые темы в конец, а не в середину,
   если не готовы сбросить `opt.best`.
7. **Клавиши 1–8.** Обработчик ловит только `/^Digit[1-8]$/`, поэтому девятая тема
   будет недоступна с клавиатуры. При добавлении темы обновите и регулярку, и
   подсказку в блоке горячих клавиш. Навигация по теме идёт через `jump()`, а не
   через `go(find(...))`: `find()` возвращает `-1`, и `go(-1)` закольцует на
   последний блок вместо того, чтобы остаться на месте.
8. **Клавиатура игнорирует ввод** в `input[type=number|range]`, события с
   meta/ctrl/alt и Enter на кнопке. При добавлении полей ввода проверьте, что
   горячие клавиши не перехватывают набор.
9. **`AudioContext` создаётся при загрузке сэмплов.** `loadE()` вызывает `ac()`,
   поэтому после старта страницы контекст уже существует в `suspended`. Не
   начинайте звук без жеста: `start()` и `micOn()` вызывают `resume()`. Не
   переносите создание контекста в обработчик каждого клика.
10. **Микрофон только в secure context.** На `file://` и по http с чужого хоста
    `getUserMedia` не сработает; ошибка отключает `opt.GM` и показывает сообщение
    в `#mst`.
11. **Калибровка длится ~11,5 с** и требует минимум 5 пойманных нот из 12. Меняя
    тайминги щелчков, синхронизируйте `setTimeout` и количество щелчков.
12. **`stop()` пересоздаёт выход.** `kill()` заново создаёт `out` и компрессор,
    `nb` — шину нот. Не сохраняйте ссылки на старые узлы между запусками.
13. **Статус голоса.** `#vst2` показывает состояние загруженных сэмплов, `#vst` —
    выбранный браузерный голос. При полной загрузке `vstat()` скрывает `#vst`
    через `style.display`, но не трогает `#vst2`. Оба спана больше не имеют
    атрибута `hidden`; не возвращайте его, иначе статус снова станет невидимым.
14. **IndexedDB для голоса удалён.** `db`, `putV` и `loadV` вырезаны: сэмплы
    всегда декодируются из `voice/`, а офлайн держится на `SHELL` в `sw.js`.
    Не возвращайте второе хранилище — оно расходилось с кешем и не читалось.
15. **Экспорт удалён.** Ветки `window.claude`, кнопки «Сохранить как файл» и
    клонирования документа больше нет. Не возвращайте её: приложение должно
    оставаться обычной страницей, а голос грузится по ссылке.
16. **`manifest.json` использует относительные пути** (`./`), чтобы работать из
    подкаталога GitHub Pages. Не заменяйте на абсолютные.
17. **Метр фиксирован: 4/4.** Метроном, `bdur`, `drawStrip`, нога и прогресс
    предполагают 4 доли в такте. Смена размера потребует правок во всех этих местах.
18. **Автотесты не покрывают акустику.** Playwright проверяет UI, данные,
    планировщик, Web Audio API, worklet-детектор и PWA, но микрофон фейковый, а
    реальный `AudioContext` не слышен. Синтаксическая проверка `node --check`
    не поймает ошибки времени выполнения и Web Audio; после правок запускайте
    `npm test` и дополняйте ручной чек-лист для звука.
19. **Тесты зависят от идентификаторов и имён.** Они обращаются к `#id`, `B`,
    `opt` и глобальным функциям напрямую. Переименование элемента или функции
    требует правки соответствующего spec-файла.
20. **Фейковый микрофон молчит.** `tests/fixtures/silence.wav` подключается флагом
    Chromium; благодаря этому нет случайных атак. Для теста атак вызывайте
    `onset(t)` напрямую и держите `xq` в будущем, иначе `gameTick` пометит ноты
    пропущенными.
21. **Калибровка в тестах идёт на фейковых часах.** `page.clock.fastForward(12000)`
    прокручивает `setTimeout`; `ctx.currentTime` при этом не двигается, поэтому
    `cal.on` заполняется от текущего аудио-времени. Не заменяйте это реальным
    ожиданием 11,5 с.
22. **Настройки, счёт и подсказки — скрытые вкладки.** В `page.locator(...).click()`
   по `#oloop`, `#ocb`, `#ogm`, `#bcal`, `#bplay` нужно сначала открыть нужный
   экран (`openTab`). Проверки текста и значений у скрытых элементов работают, а
   клики и `focus()` — нет. Не переносите поля между экранами без правки тестов.
23. **Канвас рисуется только на видимой вкладке.** `draw()` выходит при нулевой
   ширине, поэтому `#cv` живёт на «Игре»; `showView('vplay')` вызывает `draw()`,
   а `frame()` рисует только во время игры. При открытом «Счёте» канвас скрыт и
   не обновляется — это нормально, не переносите его обратно.
24. **Логотип, название и иконки — пиксельная сетка.** Шапка использует контурный
   SVG 16×16 и глифы 5×7, иконки PWA — заливной вариант. Держите целые
   координаты, `shape-rendering="crispEdges"` и одинаковую ширину строк у буквы,
   иначе пиксели «поплывут». `foot(f)` двигает `#lneedle` и `#lfoot` целыми
   пикселями: не заменяйте на `rotate`, иначе стиль ломается. После изменения
   логотипа перегенерируйте `icon-192.png`, `icon-512.png`,
   `icon-maskable-512.png` и `apple-touch-icon.png` и поднимите `VERSION`.
25. **Счёт может занимать два такта.** `k` тогда начинается с `-2`, поэтому
   проверяйте `k < 0`, а не `k == -1`; `#bars` считает номер как
   `opt.CB + it.k + 1`. Первый такт двухтактного счёта поёт только «раз» и
   «два» — это ветка `half` в `sched()`.
26. **`rec` и `best` не чистятся.** Записи привязаны к индексам `B`. После
   перестановки `EX` старые значения остаются в `localStorage`, но `recUpd()`
   отбрасывает неизвестные индексы; сбросить рекорды можно только вручную.

## Ручной чек-лист

Сначала `npm test`. Вручную остаётся то, что не слышно в headless: реальный
микрофон, задержка интерфейса, качество звука и калибровка на живом сигнале.

1. `python3 -m http.server 8000`, открыть `http://localhost:8000`, консоль без ошибок.
2. «Старт»: метроном и голос, маятник в логотипе качается влево-вправо, нога
   приподнимается на «и», полоса рисунка и прогресс двигаются.
3. Счёт: переключить «Тактов счёта» на 2 и убедиться, что сначала звучит
   «раз — два —», затем «раз, два, три, четыре».
4. Переключение темы, рисунка, темпа; кнопки ±5; клавиши `Space`, `Enter`,
   `←`/`→`, `↑`/`↓`, `-`/`=`, `L`, `N`, `1`–`8`.
5. Шапка: шестерёнка слева крайней открывает настройки, «?» справа от неё —
   подсказки, оба возвращают на игру; название собрано из пикселей.
6. Вкладка «Игра»: живой счёт, точность, серия и канвас с нотами; «Счёт»
   показывает итог, тайминг, гистограмму и таблицу рекордов; воспроизведение при
   переключении не сбрасывается, урок и настройки сохраняются.
7. Настройки: повтор, такт счёта и его длина, число тактов, голос и его
   громкость, звук рисунка и его громкость. Перезагрузка сохраняет значения и `cur`.
8. Режим игры: включить, выбрать вход, полоска уровня заходит за метку,
   калибровка, оценка попаданий, звёзды, статистика μ/σ, гистограмма; после
   уровня в таблице рекордов появляется строка с точностью и звёздами.
9. Голос: в Network видны пять `voice/*.mp3`, статус «Точный голос загружен»;
   после офлайн-перезагрузки голос тоже загружается из кеша.
10. Офлайн: DevTools → Application → Service Worker зарегистрирован; после
    перезагрузки без сети приложение открывается. Проверить, что после изменения
    `index.html` или `voice/` поднят `VERSION` и новая версия подхватывается.

## Деплой

Пуш в ветку, из которой GitHub Pages публикует корень репозитория. Перед пушем:
поднять `VERSION` в `sw.js`, убедиться, что `.nojekyll` на месте, все пути
относительные. Remote в этом клоне не настроен.
