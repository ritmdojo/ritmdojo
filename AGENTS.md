# AGENTS.md

## Что это

RitmDojo, ритм-тренажёр для гитары. Один статический сайт без сборки и зависимостей:
разметка в `index.html`, стили в `style.css`, весь скрипт в `app.js`, голосовые
сэмплы — в `voice/`.
Есть PWA-обвязка (`manifest.json`, `sw.js`, иконки) для установки и офлайн-работы.
Публикуется как GitHub Pages из корня репозитория.

## Быстрый старт

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

Открывать через `file://` нельзя: не зарегистрируется service worker, а микрофон и
`AudioWorklet` требуют secure context (`localhost` или https).

Сборки и линтера нет. `package.json` содержит только dev-зависимость
`@playwright/test`; на работу самого сайта она не влияет.

## Тесты

```bash
npm install
npx playwright install chromium   # если браузера ещё нет в кеше
npm test                          # весь suite, ~40 с
npm run test:headed               # с видимым браузером
npm run test:report               # HTML-отчёт после падения
```

Playwright сам поднимает `python3 -m http.server 4173` через `webServer` в
`playwright.config.js`, отдельно запускать сервер не нужно. Если порт 4173 занят,
`reuseExistingServer` переиспользует его локально (но не в CI).

Устройство тестов:

- `tests/helpers.js`: `boot(page, state)` (состояние кладётся через
  `addInitScript` один раз, чтобы пережить `reload`), ожидание голоса, чтение
  `opt`/`localStorage`, `openTab(page, 'play'|'score'|'settings'|'help')`,
  открытие `<details>`. Экраны переключаются кнопками-переключателями, поэтому
  `openTab` смотрит на `aria-pressed` и нажимает только нужную.
- `tests/boot.spec.js`, `navigation.spec.js`, `keyboard.spec.js`,
  `playback.spec.js`, `settings.spec.js`, `voice.spec.js`, `game.spec.js`,
  `pwa.spec.js`, `tabs.spec.js`, `records.spec.js`, `appearance.spec.js`:
  по доменам поведения.
- Шапка и подсказки проверяются в `tabs.spec.js`: порядок «логотип → Счёт → ?
  → шестерёнка», пиксельные `rect` только у `#wm` (у `#bhelp` текстовый глиф, у
  `#bset` и транспорта обычные SVG 20×20), одна строка прогресса, темп и
  транспорт в одной строке, порядок «реплей → назад → плей → дальше», все
  кнопки 40×40, `?` прижат вправо, справка идёт «Как играть → Как заниматься →
  Горячие клавиши».
- Таблица рекордов проверяется в `records.spec.js`: пустое состояние, сортировка,
  запись `opt.rec` через `result()` и защита рекорда от слабого повтора.
- Настройки и результат живут на скрытых вкладках, поэтому тесты, которые
  нажимают `#oloop`, `#ogm`, `#bcal` или проверяют `#rt`/`#hst`, сначала вызывают
  `openTab()` (кроме проверок текста/значений у скрытых элементов).
- Живой HUD (`#hud`, `#cv`, `#fb`, `#pop`) теперь на «Игре», поэтому проверки
  канваса идут без переключения на «Счёт»: скрытый канвас имеет нулевой размер.
- Итог уровня проверяется в `#pop` поверх канваса: он гаснет сам через 2 с,
  `#fb` остаётся для мгновенной оценки отдельной ноты.
- Микс и производительность проверяются в `playback.spec.js`: частоты и тип
  щелчка, панорама шин (`StereoPanner`), а также что кадр не меряет разметку
  (`getBoundingClientRect` не вызывается из `draw`).
- Голос грузится из `voice/*.mp3`; тесты проверяют файлы через `request`, а
  `waitVoice()` ждёт декодирования всех пяти слов.
- В `playwright.config.js` по умолчанию `serviceWorkers: 'block'`, иначе кеш
  мешает изоляции; `pwa.spec.js` включает их через `test.use`.
- Микрофон подменяется фейковым устройством Chromium с файлом
  `tests/fixtures/silence.wav`; это даёт детерминированные нулевые атаки.
  Реальную акустику и задержку оборудования тесты не проверяют.
- Внутренние функции (`B`, `opt`, `g`, `e`, `onset`, `result`, `start`, ...)
  доступны из `page.evaluate`, потому что скрипт классический и живёт в
  глобальной области. Переименование этих сущностей ломает тесты.
- `page.clock` используется для калибровки: `fastForward(12000)` проходит
  `setTimeout` на 11,5 с без реального ожидания.

## Проверки перед коммитом

```bash
npm test
```

Синтаксис скрипта (классический script, не модуль):

```bash
node --check app.js
```

Целостность голосовых файлов:

```bash
python3 - <<'EOF'
from pathlib import Path
for p in sorted(Path('voice').glob('*.mp3')):
    d = p.read_bytes()
    print(p, len(d), d[:3])
EOF
```

Должно быть пять файлов (`raz`, `dva`, `tri`, `chetyre`, `i`) с началом `ID3`.

После правки `index.html`, `style.css` или `app.js` обязательно поднять `VERSION`
в `sw.js`. Иначе браузер продолжит отдавать старую версию из кеша (стратегия
cache-first).

## Архитектура

`app.js` подключается классическим `<script src>` в конце `body` и выполняется в
глобальной области, без модулей и без фреймворка: поэтому тесты зовут `B`, `opt`,
`draw` и остальные функции прямо из `page.evaluate`. Разметка статическая, все
элементы ищутся по `id` через `$ = s => document.getElementById(s)`.
Обработчики навешиваются в конце скрипта, а не атрибутами `onclick` в HTML.

### Экраны и вкладки

Разметка разделена на четыре `section.view`: `#vplay` (урок, транспорт и живой
результат), `#vscore` (итог, тайминг и таблица рекордов), `#vset` (все настройки)
и `#vhelp` (подсказки). Отдельной вкладки «Игра» нет: `showView(v)` переключает
`hidden` и ставит `aria-pressed` трём кнопкам-переключателям — `#tscore`,
`#bset` и `#bhelp`. Повторное нажатие любой из них возвращает на игру, поэтому
«Счёт», «?» и шестерёнка ведут себя одинаково, а выбранный экран не сохраняется.

Шапка: слева `.brand` (логотип `#logo` и название `h1`), справа крайними —
«Счёт» `#tscore`, «?» `#bhelp` и шестерёнка `#bset`. Это обычные кнопки с
обычными иконками: «?» — текстовый глиф, шестерёнка — штриховой SVG (Lucide
settings), пиксель-арт остался только у логотипа и названия.

Название `h1` — не текст, а пиксельный SVG `#wm`: глифы 5×7 лежат в объекте `PF`,
функция `pxs()` превращает строки из `0/1/2` в `rect` (символ `2` — красный
акцент, точка у «i» и «j»). Обычные пиксели залиты `currentColor` (цвет `h1`),
акцентные — `var(--need)`, поэтому название само переключается между светлой и
тёмной темой. Для доступности рядом стоит `<span class="sr">`. При правке глифов
следите, чтобы у всех строк одной буквы была одинаковая ширина.

Логотип `#logo` — inline SVG 30×13 с `shape-rendering="crispEdges"`: пиксельный
кед в профиль носком вправо. Рисунок задан строками `SHOE` (символы `R`, `W`,
`G`, точка — прозрачность) в `logoArt()`, контур считается по соседям. Кед разделён
на три группы: `#lback` (пятка и голенище, x 0–13, неподвижна), `#lmid`
(передняя часть стопы, x 14–19) и `#ltoe` (носок, x 20–29), плюс две метки
удара `#ltap`. `foot(f)` на «и» поднимает `#lmid` на 1 пиксель, а `#ltoe` на 2 —
пятка остаётся осью качения, метки гаснут на подъёме и зажигаются на доле.
Цвета берутся из `--fg`, `--need`, `--paper`, `--mut`, так что логотип
адаптируется к теме. Иконки PWA — тот же кед на тёмном скруглённом квадрате; при
смене рисунка их нужно перегенерировать в размерах 192, 512, maskable 512 и 180.

### Данные упражнений

```js
const H = .5, T = 1/3, S = .25, X = 1/6;       // длительность шага в долях
const EX = [{ t: 'Четверти', l: [60, 80, 100], p: [['Все четверти', g('Xxxx', 1)], ...] }, ...];
const B = [];                                    // плоский список блоков
EX.forEach((x, xi) => x.p.forEach((p, pi) => x.l.forEach((v, ti) =>
  B.push({ xi, pi, ti, bpm: v }))));
```

- `EX` — темы. `t` название, `l` три темпа (чипы), `p` пары «название, события».
- Событие это `[начало в долях от 0 до 4, акцент, длительность в долях]`.
- `g(pattern, step)` строит события из строки: `X` акцентированная нота, любой
  другой символ кроме `.` обычная нота, `.` пауза. Пробелы игнорируются.
  Длительность каждого события равна `step`, включая последнее. Поэтому у рисунка,
  который заполняет такт целиком, последняя нота тоже заканчивается ровно на 4
  долях, как и у `e()`. Если строка короче такта или кончается паузой, нота
  остаётся длиной `step`: тянуть её до конца такта нельзя, иначе пауза в конце
  рисунка исчезнет.
- `e(offsets, off)` строит события из абсолютных смещений: длительность считается
  до следующего события, последнее тянется до конца такта (4 доли). Второй аргумент
  `off` переключает трактовку акцента: без него акцентируются доли на сильной позиции
  (`s % 1 == 0`), с `1` — синкопы (`s % 1 != 0`).
- `B` упорядочен по теме, затем по рисунку, затем по темпу. Индекс `B` это
  идентификатор блока: он хранится в сохранениях, используется в прогрессе,
  клавишах и статистике. Перестановка или вставка блоков ломает сохранённые звёзды.

Поиск блока: `find(xi, pi, ti)` (для неизвестной комбинации возвращает `-1`).
Навигация: `go(i)` (с закольцовыванием по всему `B`), `pat(±1)` (следующий
рисунок внутри текущего темпа 0). Селекторы темы, рисунка, темпа и клавиши
`1`–`8` ходят через `jump(xi, pi, ti)`: он молча пропускает `-1`, иначе
несуществующий блок закольцевался бы в последний.

### Планировщик воспроизведения

- `start(countIn)` создаёт/возобновляет `AudioContext`, сбрасывает состояние игры,
  ставит `sc = cur` (курсор планировщика), `k = countIn ? -1 : 0` и запускает
  `setInterval(tick, 40)`.
- `sched()` планирует один такт вперёд: метроном (`click`), голос (`say`), ноты
  рисунка (`note`), события для игры (`xq`) и бары для отрисовки (`bh`).
  Такт всегда 4/4, длительность `4 * spb`, где `spb = 60 / bpm`.
- `tick()` досрочно планирует всё, что попадает в окно `max(.4, 360 / bpm)` секунд.
- `frame()` это `requestAnimationFrame`-цикл. Он читает очередь `q`, двигает
  визуальный курсор `cur`, обновляет прогресс, фазу, ногу, полосу рисунка и
  вызывает `gameTick` в режиме игры. Визуальное состояние всегда идёт за очередью
  уже запланированных тактов, а не за `sc`.
- Такты блока: `k < 0` счёт перед стартом, `0..L-1` «Слушай», `L..L+P-1` «Играй»,
  `L+P` итоговый такт в режиме игры. Число тактов и `bdur()` учитывают
  дополнительный такт `opt.GM`.
- Счёт бывает на один или два такта (`opt.count` + `opt.CB`), поэтому `start()`
  ставит `k = -opt.CB`. В первом такте двухтактного счёта звучат только «раз»
  (доля 1) и «два» (доля 3), во втором — «раз, два, три, четыре». Слог «и» в
  тактах счёта не поётся: он остаётся только в тактах слушания и игры. Визуально
  `#bars` показывает «счёт 1 из 2» и «счёт 2 из 2».
- `stop()` останавливает таймер, глушит звук и пересоздаёт выход (`kill()`).

Темп: `bpmOf(i)` берёт темп блока плюс глобальный `shift`, зажатый в диапазоне
30–240. `shift` меняется кнопками ±5 и клавишами `-`/`=`, хранится отдельно от `opt`.

### Микс и разведение по панораме

Граф собирается в `kill()`: `out` (gain 0.85) → компрессор-ограничитель
(threshold −6 dB, ratio 4, attack 3 мс) → выход. От `out` отходят три шины:

- `nb` — ноты рисунка, через `StereoPanner` +0.18 (правее).
- `cb` — щелчки метронома, через `StereoPanner` −0.45 (левее).
- голос — в центр, напрямую в `out`, с общей подстройкой `opt.G/100 * .85`.

Щелчок метронома — треугольная волна: 2400 Гц на первой доле (0.6), 2000 Гц на
остальных (0.52), 1500 Гц на «и» (0.16). Раньше был синус 1600/1050/720 Гц, и его
не было слышно: он попадал в формант голоса, а компрессор ratio 12 съедал его
совсем. Замер в своей полосе (offline-рендер, Гоэрцель) даёт +28…+41 дБ над
фоном вместо +8…+23 дБ, пик микса при этом 0.86, клиппинга нет.

`click(t, f, v)` и `note(t, acc)` — единственные места, где задаются уровни
щелчка и нот. Калибровка бьёт теми же щелчками (`click(t, i%4?2000:2400, .8)`).

### Режим игры

- Игра (`opt.GM`, по умолчанию вкл) и микрофон (`opt.MICON`, по умолчанию выкл)
  разделены. Анимация окна нот, оценка, тап по `#cv` и клавиша `X` работают без
  микрофона; `opt.GM` больше не выключается из-за входа.
- Микрофон включается только чекбоксом «Подключить гитару»: `micOn()`
  запрашивает `getUserMedia` с выключенными echoCancellation/
  noiseSuppression/autoGainControl. До галочки браузер разрешение не спрашивает
  (Safari показывает диалог синхронно, и `start()` его больше не вызывает при
  `opt.MICON == false`). Если по списку устройств выход — не наушники (`hp()`
  ловит «динамик/speaker/монитор/встроен»), `micOn()` ничего не включает:
  снимает `opt.MICON`, оставляет игру и просит надеть наушники. Пустой или
  неизвестный ярлык устройства проверку не проваливает. Неизвестно, как звучит
  «Dynamics»? Список `hp()` пополнять по реальным ярлыкам.
- Детектор атак `class Det` сериализуется через `Det.toString()` в исходник
  `AudioWorklet` (`WK`, строка около 209). Поэтому `Det` обязан быть
  самодостаточным: никаких ссылок на внешние переменные, константы или методы.
  При недоступности `AudioWorklet` используется `createScriptProcessor` и тот же `Det`.
- `onset(t)` сопоставляет найденную атаку с ближайшей ожидаемой нотой (окно 130 мс),
  вычитая задержку `lat()`. Оценка: `≤ 45 мс` идеально, `≤ 90 мс` хорошо,
  иначе рано/поздно; пропущенная ожидаемая нота даёт «Мимо», а лишняя атака
  попадает в `pv` с `r = 'x'` и рисуется красным ромбом.
- Тап по канвасу `#cv` — источник ввода ритма: `pointerdown` при включенной
  игре и играющем транспорте зовёт `onset(ctx.currentTime + lat()/1000)`. То
  же делает клавиша `X` (`KeyX`) — фоллбэк, когда микрофон недоступен. В демо
  оба источника игнорируются. `#cv{touch-action:none}` блокирует скролл свайпом.
- Демо-режим (`opt.DEM`, кнопка `#bdem` справа от строки темпа): приложение само
  делает идеальные удары — `gameTick` стреляет `onset(e.t + lat()/1000)` по
  каждой ожидаемой ноте, режиссёрского звука «за игрока» нет. Микрофон в демо
  не запрашивается (`start()` пропускает `micOn()`), а `result()` в демо не
  пишет `best`/`rec`/`HI` (ставить отметку `if(opt.DEM)return R` до записи).
- Точность: `(p + .6*g - .3*x) / n`. Уровень пройден при 60 %, звёзды при 75 % и
  90 %. Множитель `1 + min(3, combo >> 3)`. Рекорд и звёзды хранятся в `opt`.
- Живой результат (`#hud`) живёт на игровом экране и объединён с полосой
  рисунка: строка статуса `.stat` (`#phase` слева, `#bars` рядом, справа счёт,
  множитель с серией и точность), имя рисунка `#pname`, кружок `#bhud` прижат
  вправо, полоса `#strip`, `#cbar` с восемью делениями до множителя, канвас
  `#cv` и `#fb` с оценкой. Подсказки к окну лежат в `#hb` и открываются кружком
  `#bhud`. На экране «Счёт» остались итог, тайминг `#tm` с гистограммой `#hg` и
  таблица рекордов.
- Калибровка начинается со счёта: один такт «раз, два, три, четыре» на 60 BPM
  (4 с), затем 12 щелчков калибровки; таймер итога срабатывает на ~15,7 с, в
  тестах `fastForward(20000)`. Калибровка привязана ко входу: `opt.CALP`
  хранит значения по deviceId, `opt.CALDEV` — откалиброванный вход; при смене
  входа `micOn()` берёт значение из `opt.CALP` или снимает `opt.CALD`.
- `result(bi)` вызывается на итоговом такте: считает точность и звёзды, копит
  `score`, обновляет `opt.best` и `opt.rec[bi] = { a, st, bpm }` (только если
  точность выше прежней; звёзды не понижаются) и вызывает `recUpd()`.
- `recUpd()` строит `#rt`: лучшие 12 блоков по звёздам, затем по точности, затем
  по темпу; показывает номер урока, тему с рисунком, темп, точность и звёзды.
- `endBlock()` после итогового такта либо переходит к следующему блоку, либо
  повторяет текущий, если уровень не пройден. При `opt.skip` (по умолчанию)
  первые две неудачи повторяются без тактов «Слушай»: `forceL(0)` временно
  ставит `opt.L = 0`, а с третьей неудачи `unforce()` возвращает прежнее
  значение, и прослушивание снова звучит. `unforce()` также вызывают пройденный
  уровень, ручной старт и остановка. `sched()` пересчитывает `TOT` после смены
  `opt.L`, иначе `#bars` покажет старый размер блока.
- Итог уровня всплывает над канвасом в `#pop`: «Удовлетворительно N%» за одну
  звезду, «Хорошо N%» за две, «Отлично N%» за три и «Неудача N%» без звёзд.
  Первые три окрашены в `--ok`, неудача — в `--need`; через 2 с попап гаснет
  (`popOff()`), а `stop()` и `start()` скрывают его сразу. `#fb` под канвасом
  показывает мгновенную оценку отдельной ноты («Идеально», «Хорошо», «Рано»,
  «Поздно», «Мимо») по центру.
  После счёта, когда начинается первый такт, `#pop` на секунду показывает
  «Погнали!»; голос при этом не меняется и по-прежнему поёт «четыре».
- Мгновенная оценка `#fb` гаснет сама: `flash()` через 0,9 с ставит класс
  `fade` (прозрачность 0 за 0,4 с) и затем очищает текст; `fbOff()` снимает
  таймер (`fbT`) и вызывается из `stop()`.
- `#pop` скрывается при смене фазы (`Слушай`/`Играй`/`Счёт`), поэтому итог
  прошлого блока не висит поверх нового такта; во время `Итог` попап остаётся
  до смены фазы или до `popOff()`.

### Голос

- Пять MP3 лежат в `voice/` под ASCII-именами: `raz.mp3`, `dva.mp3`, `tri.mp3`,
  `chetyre.mp3`, `i.mp3`. Карта `VF` сопоставляет русские слова файлам, `loadE()`
  грузит их через `fetch` по относительным ссылкам и декодирует в `AudioBuffer`,
  обрезает ведущую тишину и считает `PC` — положение ударной гласной по
  спектрограмме. Автосмещение `opt.O[слово] = -PC` выставляется только если для
  слова ещё нет сохранённого значения, поэтому ручная подстройка не перетирается.
- Если загружены все пять слов, `say()` играет буферы; иначе используется
  `speechSynthesis` с русским голосом и поправкой `opt.D`. При ошибке загрузки
  (нет сети и нет кеша) слово просто остаётся незагруженным, страница не падает.
- Имена файлов продублированы в `VF` и в списке `SHELL` в `sw.js`: новый файл без
  записи в `SHELL` не попадёт в офлайн-кеш.
- `start()` задерживает старт на максимальное отрицательное смещение слова, чтобы
  ни одно слово не попало в прошлое.
- Хранилища голосов в IndexedDB больше нет: `db`, `putV` и `loadV` удалены.
  Сэмплы всегда берутся из `voice/`, офлайн обеспечивает service worker.

### Сохранения

- `localStorage['rt2']` = `{ cur, shift, opt }`. Читается один раз при старте,
  `opt` мержится через `Object.assign`: новые поля из сохранения переживают
  обновление, а неизвестные поля не удаляются.
- `opt` содержит: `loop`, `count`, `CB` (тактов счёта 1–2), `L` (тактов слушания 0–8),
  `P` (тактов игры 1–16), `V` (голос), `D` (задержка голоса, мс), `G` (громкость
  голоса, %), `N` (звук рисунка), `NP` (рисунок и в игре), `NG` (громкость
  рисунка, %), `PIT` (высота ноты рисунка, Гц), `GM` (игра, по умолчанию
  включена), `MICON` (микрофон по галочке «Подключить гитару», по умолчанию выкл), `S` (чувствительность 0–100), `skip` (пропускать «Слушай» первые
  два повтора), `DE` (демо-режим), `CAL`/`CALD` (калибровка), `CALDEV`/`CALP`
  (калибровка по входу: устройство и значения по deviceId), `OUT`/`MIC`
  (устройства), `HI` (рекорд), `best` (звёзды по индексу блока), `rec` (лучшая точность, звёзды и темп по индексу
  блока), `O` (смещения слов, мс).
  В дефолтном литерале `opt.O` лежат латинские ключи `c/t/n/v`; реальные смещения
  пишутся по русским словам при `decodeV` и затем сохраняются.
- `best`, `rec` и `HI` привязаны к индексам `B`; при изменении `EX` старые
  рекорды становятся неверными. `hst` считает сумму звёзд из `B.length * 3`.
- Все обращения к `localStorage` обёрнуты в `try/catch` и молча игнорируют ошибки
  (приватный режим, запрет хранилища). Логов в консоли нет.

### Экран игры

Экран собран из трёх карточек: прогресс (`#pg`), выбор урока и транспорт,
перформанс (`#hud`) с полосой рисунка и канвасом. Минимальный viewport —
iPhone 13 mini, 375×812 (`appearance.spec.js`); страница занимает всю высоту
`100dvh`, `body` не прокручивается, а свободное место забирает канвас. Поэтому:

- прогресс — тонкая полоса и одна строка подписей (`.pgr` с
  `flex-wrap:nowrap`), «Прошло / Осталось / Всего / Урок N из M» не переносятся;
- в карточке урока два селекта в один ряд (`#vplay .row label` с `min-width`
  120 px). Ниже строка `.ctl`: группа темпа (`#m5`, чипы `#tempos`, `#p5`)
  слева и `#bdem` «Демо» справа. Затем строка `.tbtns` — сетка
  `1fr auto 1fr`: слева `#brst` и `#bprev` (прижаты к плей), по центру
  строго центр карточки `#bplay`, справа `#bnext`. Тест сравнивает середину
  `#bplay` с серединой карточки;
- `.tbtns` всегда в одну строку: `#brst` (реплей), `#bprev` (назад), `#bplay`,
  `#bnext`. Все кнопки 40×40, включая `#bplay`; на экранах ≤430 px — 36×36.
  Иконки 20×20 — обычные штриховые SVG (rotate-ccw, skip-back, play, pause,
  skip-forward), собираются функцией `ic(body, cls, fill)`; пиксель-арта нет.
  `#bdem` — текстовая кнопка того же роста (36/40), состояние — `aria-pressed`;
- `#bpm` визуально скрыт классом `.sr`: текущий темп показывает активный чип
  `#tempos`, а `#m5`/`#p5` — компактные `−`/`+` по краям чипов.

У `#bplay` две иконки — play и pause; класс `.on` на кнопке переключает их, а
подпись для скринридера лежит в `#bplaytx` («Старт (пробел)» / «Пауза
(пробел)»). Функция `playUI(on)` обновляет и то, и другое.

Канвас `#cv` растягивается по высоте: `.cwrap` это `flex:1` с `min-height:96px`,
а сам канвас лежит в нём `absolute; inset:0`. Без подписей «Нужно»/«Сыграно»:
что где, объясняет поповер `#hb`. Он позиционирован `absolute` внутри `#hud`,
поэтому не добавляет высоту и не вызывает прокрутку. Тот же `.cwrap` держит
попап `#pop` по центру канваса.

### Производительность

Главный поток не должен мешать планировщику, иначе в аудио появляются сбои.
Правила, которые держат кадр дешёвым:

- размер канвы меряет `ResizeObserver` (`cvRO`), а не `getBoundingClientRect` в
  каждом кадре; `cvW`/`cvH` хранят последние ширину и высоту, `sizeCv()`
  ограничивает `devicePixelRatio` двойкой, а `draw()` считает `y1`/`y2` от
  высоты, поэтому ноты не привязаны к 96 px;
- цвета темы кэширует `colors()` (`CC`), сброс — через `MutationObserver` на
  `data-theme` и `matchMedia('(prefers-color-scheme:dark)')`;
- `frame()` пишет в DOM только при изменении: фаза, счётчик тактов, курсор
  полосы и подсветка ячейки сетки обновляются по ключу (`lastPh`, `lastK`,
  `lastPct`, `nowIdx`), а не каждый кадр;
- `prog()` считает суммарную длительность всех 123 блоков через `progData()`
  (кэш по `shift|L|P|GM`) и переписывает подписи, только когда меняется текст;
- `hudUpd()` тоже пишет только изменения и вызывается из `gameTick` не чаще
  10 раз в секунду (`hudT`);
- массивы `xq`, `nv`, `pv`, `bh` чистятся на месте функцией `compact()`, без
  новых массивов на кадр;
- `foot()` и `drawStrip()` помнят последнее состояние и не трогают атрибуты
  без нужды.

Профиль в Chromium с троттлингом CPU ×4, DPR 3 и включённой игрой: `draw`
1.63 → 0.37 мс на кадр, `gameTick` 1.77 → 0.41 мс, `getBoundingClientRect` из
профиля исчез совсем.

## Подводные камни

1. **Service worker отдаёт кеш первым.** Изменили `index.html`, `style.css` или
   `app.js` — поднимите `VERSION` в `sw.js`. Новый статический файл нужно добавить
   в `SHELL`, иначе офлайн он не загрузится. `sw.js` намеренно не кешируется.
2. **Голос — внешние файлы.** Пять MP3 лежат в `voice/`, имена — часть контракта
   `VF`. Переименование требует правки `VF`, `SHELL` в `sw.js` и `tests/voice.spec.js`.
   Файлы должны начинаться с `ID3`; битый MP3 молча выпадает из набора, и голос
   переключается на браузерный.
3. **`Det` уезжает в worklet через `toString()`.** Любая внешняя ссылка внутри
   класса (константа, хелпер, `opt`) сломает детектор в worklet-режиме. В
   ScriptProcessor-режиме тот же класс работает в основном потоке, поэтому
   расхождение легко не заметить.
4. **Два курсора.** `sc` — что уже поставлено в очередь, `cur` — что сейчас на
   экране. Не используйте `sc` для отрисовки и не двигайте `cur` вручную во время
   проигрывания: `frame()` сам переключит блок на границе такта.
5. **Единицы — доли, не миллисекунды.** Все события и `drawStrip` работают в долях
   от 0 до 4. `drawStrip` подбирает сетку из фиксированного набора
   `[.5, 1/3, .25, 1/6, .125]`; событие со смещением, не кратным 1/8, отрисуется
   по сетке 1/8 и будет выглядеть неверно. Новые рисунки держите в этих долях.
   Подписи сетки: на долях цифры, на 8-х «и», а в шестнадцатых (`u = .25`)
   дополнительно «е» на 1/16 и «а» на 3/16 — так же, как в названиях рисунков.
6. **Порядок `B` — часть контракта.** Он влияет на сохранённые звёзды, прогресс,
   номера блоков в HUD и клавиши. Вставляйте новые темы в конец, а не в середину,
   если не готовы сбросить `opt.best`.
7. **Клавиши 1–8.** Обработчик ловит только `/^Digit[1-8]$/`, поэтому девятая тема
   будет недоступна с клавиатуры. При добавлении темы обновите и регулярку, и
   подсказку в блоке горячих клавиш. Навигация по теме идёт через `jump()`, а не
   через `go(find(...))`: `find()` возвращает `-1`, и `go(-1)` закольцует на
   последний блок вместо того, чтобы остаться на месте.
8. **Клавиатура игнорирует ввод** в `input[type=number|range]`, события с
   meta/ctrl/alt и Enter на кнопке. При добавлении полей ввода проверьте, что
   горячие клавиши не перехватывают набор.
9. **`AudioContext` создаётся при загрузке сэмплов.** `loadE()` вызывает `ac()`,
   поэтому после старта страницы контекст уже существует в `suspended`. Не
   начинайте звук без жеста: `start()` и `micOn()` вызывают `resume()`. Не
   переносите создание контекста в обработчик каждого клика. `start()` больше не
   трогает микрофон, если `opt.MICON` выключен, поэтому первый старт не вызывает
   диалог разрешения, а `frame()` продолжает идти и после его закрытия.
10. **Микрофон только в secure context.** На `file://` и по http с чужого хоста
    `getUserMedia` не сработает; ошибка снимает `opt.MICON` и показывает сообщение
    в `#mst`, а игра продолжается тапом и клавишей `X`.
11. **Калибровка длится ~11,5 с** и требует минимум 5 пойманных нот из 12. Меняя
    тайминги щелчков, синхронизируйте `setTimeout` и количество щелчков.
12. **`stop()` пересоздаёт выход.** `kill()` заново создаёт `out` и компрессор,
    `nb` — шину нот. Не сохраняйте ссылки на старые узлы между запусками.
13. **Статус голоса.** `#vst2` показывает состояние загруженных сэмплов, `#vst` —
    выбранный браузерный голос. При полной загрузке `vstat()` скрывает `#vst`
    через `style.display`, но не трогает `#vst2`. Оба спана больше не имеют
    атрибута `hidden`; не возвращайте его, иначе статус снова станет невидимым.
14. **IndexedDB для голоса удалён.** `db`, `putV` и `loadV` вырезаны: сэмплы
    всегда декодируются из `voice/`, а офлайн держится на `SHELL` в `sw.js`.
    Не возвращайте второе хранилище — оно расходилось с кешем и не читалось.
15. **Экспорт удалён.** Ветки `window.claude`, кнопки «Сохранить как файл» и
    клонирования документа больше нет. Не возвращайте её: приложение должно
    оставаться обычной страницей, а голос грузится по ссылке.
16. **`manifest.json` использует относительные пути** (`./`), чтобы работать из
    подкаталога GitHub Pages. Не заменяйте на абсолютные.
17. **Метр фиксирован: 4/4.** Метроном, `bdur`, `drawStrip`, нога и прогресс
    предполагают 4 доли в такте. Смена размера потребует правок во всех этих местах.
18. **Автотесты не покрывают акустику.** Playwright проверяет UI, данные,
    планировщик, Web Audio API, worklet-детектор и PWA, но микрофон фейковый, а
    реальный `AudioContext` не слышен. Синтаксическая проверка `node --check`
    не поймает ошибки времени выполнения и Web Audio; после правок запускайте
    `npm test` и дополняйте ручной чек-лист для звука.
19. **Тесты зависят от идентификаторов и имён.** Они обращаются к `#id`, `B`,
    `opt` и глобальным функциям напрямую. Переименование элемента или функции
    требует правки соответствующего spec-файла.
20. **Фейковый микрофон молчит.** `tests/fixtures/silence.wav` подключается флагом
    Chromium; благодаря этому нет случайных атак. Для теста атак вызывайте
    `onset(t)` напрямую и держите `xq` в будущем, иначе `gameTick` пометит ноты
    пропущенными.
21. **Калибровка в тестах идёт на фейковых часах.** `page.clock.fastForward(20000)`
    прокручивает `setTimeout`; `ctx.currentTime` при этом не двигается, поэтому
    `cal.on` заполняется от текущего аудио-времени. Щелчки калибровки начинаются
    после счёта (≈ `dO + 4.2` с от нуля), таймер — на ~15,7 с. Не заменяйте это
    реальным ожиданием.
22. **Настройки, счёт и подсказки — скрытые вкладки.** В `page.locator(...).click()`
   по `#oloop`, `#ocb`, `#ogm`, `#bcal`, `#bplay` нужно сначала открыть нужный
   экран (`openTab`). Проверки текста и значений у скрытых элементов работают, а
   клики и `focus()` — нет. Не переносите поля между экранами без правки тестов.
23. **Канвас рисуется только на видимой вкладке.** `draw()` выходит при нулевой
   ширине, поэтому `#cv` живёт на «Игре»; `showView('vplay')` вызывает `draw()`,
   а `frame()` рисует только во время игры. При открытом «Счёте» канвас скрыт и
   не обновляется — это нормально, не переносите его обратно.
24. **Пиксель-арт только у логотипа и названия.** Шапка использует SVG 30×13
   (кед) и глифы 5×7, иконки PWA — тот же кед на тёмном квадрате. Кнопки
   «?», шестерёнка и транспорт — обычные SVG (`ic()`), не превращайте их обратно
   в `rect`-сетку и не возвращайте им `shape-rendering="crispEdges"`. У кеда и
   глифов держите целые координаты и одинаковую ширину строк у буквы, иначе
   пиксели «поплывут». `foot(f)` двигает
   только `#lmid` (передняя часть стопы, на 1 пиксель) и `#ltoe` (носок, на 2)
   целыми пикселями, `#lback` с пяткой неподвижен, а `#ltap` зажигается на доле:
   не заменяйте на `rotate`, не двигайте пятку и не добавляйте дробные координаты,
   иначе стиль ломается. Цвета — только через переменные темы (`R` — `--need`,
   `W` — `--paper`, `G` — `--mut`, контур — `--fg`). После изменения логотипа
   перегенерируйте `icon-192.png`, `icon-512.png`, `icon-maskable-512.png` и
   `apple-touch-icon.png` и поднимите `VERSION`.
25. **Счёт может занимать два такта.** `k` тогда начинается с `-2`, поэтому
   проверяйте `k < 0`, а не `k == -1`; `#bars` считает номер как
   `opt.CB + it.k + 1`. Первый такт двухтактного счёта поёт только «раз» и
   «два» — это ветка `half` в `sched()`. В тактах счёта (`k < 0`) слог «и» не
   поётся, хотя тихий щелчок на слабой доле остаётся.
26. **`rec` и `best` не чистятся.** Записи привязаны к индексам `B`. После
   перестановки `EX` старые значения остаются в `localStorage`, но `recUpd()`
   отбрасывает неизвестные индексы; сбросить рекорды можно только вручную.
27. **Итог уровня живёт в попапе `#pop`.** Он лежит в `.cwrap` поверх канваса,
   гаснет сам через 2 с и очищается в `stop()`/`start()`. Текст зависит от
   звёзд: «Удовлетворительно», «Хорошо», «Отлично» или «Неудача». `#fb` больше
   не получает итог: там только мгновенная оценка ноты, по центру.
   «Погнали!» — такой же попап на переходе `k=-1 → 0`, голос не меняется.
28. **Кнопки транспорта — иконки в карточке урока.** `#brst`, `#bprev`,
   `#bplay` и `#bnext` лежат в `.tbtns` внутри карточки выбора урока, порядок
   именно такой: сначала реплей, потом назад. Все четыре одного размера 40×40
   (на экранах ≤430 px — 36×36), не выделяйте `#bplay` шириной. Подпись `#bplay`
   лежит в `#bplaytx`, а не в самой кнопке: `toHaveText` в тестах проверяет
   `#bplay`, поэтому текст должен оставаться единственным текстом кнопки.
29. **Не мерите разметку в кадре.** `draw()` берёт ширину и высоту из
   `cvW`/`cvH` (заполняет `ResizeObserver`), а не из `getBoundingClientRect()`.
   Возврат замера в кадр вернёт главный тормоз: на слабом телефоне это и есть
   источник сбоев звука.
30. **Поповер подсказок не занимает высоту.** `#hb` лежит внутри `#hud` с
   `position:absolute` и открывается кружком `#bhud`. Сделаете его обычным
   блоком — экран перестанет влезать по высоте, и это поймает
   `appearance.spec.js`.
31. **Кед идёт за слышимым временем.** `visT(t)` вычитает
   `outputLatency`/`baseLatency` и добавляет 8 мс (полкадра). Не считайте `foot(f)`
   и курсор полосы от `ctx.currentTime` напрямую: анимация отстанет от звука.
   `draw()` делает ту же поправку.
32. **Повторы меняют `opt.L` на ходу.** При `opt.skip` первые две неудачи
   повторяются с `L = 0` (`forceL(0)`), с третьей `unforce()` возвращает прежнее
   значение. `forceL()`/`unforce()` трогают `opt.L` во время игры, поэтому
   `sched()` пересчитывает `TOT` после смены блока. `unforce()` вызывают
   пройденный уровень, `start()` и `stop()`.

## Ручной чек-лист

Сначала `npm test`. Вручную остаётся то, что не слышно в headless: реальный
микрофон, задержка интерфейса, качество звука и калибровка на живом сигнале.

1. `python3 -m http.server 8000`, открыть `http://localhost:8000`, консоль без ошибок.
2. «Старт»: метроном и голос, кед в логотипе притопывает носком (пятка стоит,
   передняя часть стопы приподнимается на 1 пиксель, носок на 2 вверх на «и»)
   и попадает в звук без заметного отставания, полоса рисунка и прогресс
   двигаются. В наушниках щелчок метронома должен быть
   слышен на каждой доле, а не только на первой, и звучать левее голоса.
3. Счёт: переключить «Тактов счёта» на 2 и убедиться, что сначала звучит
   «раз — два —», затем «раз, два, три, четыре» без «и».
4. Переключение темы, рисунка, темпа; кнопки ±5 по краям чипов темпа, темп и
   транспорт в одной строке; порядок «реплей, назад, старт, дальше», все четыре
   кнопки одного размера; клавиши `Space`, `Enter`, `←`/`→`, `↑`/`↓`, `-`/`=`,
   `L`, `N`, `1`–`8`.
5. Шапка: слева логотип и пиксельное название, справа крайними «Счёт», «?» и
   шестерёнка с обычными иконками. Каждая из трёх кнопок открывает свой экран,
   повторное нажатие возвращает на игру. Кружок «?» у имени рисунка прижат
   вправо и открывает подсказки к окну, они закрываются по Esc или клику мимо.
   В справке сначала «Как играть», потом «Как заниматься» и горячие клавиши.
   Проверьте светлую и тёмную тему: кед и название должны оставаться
   контрастными.
6. Игровой экран: живой счёт, точность, серия и канвас с нотами; на 375×812
   весь экран виден без прокрутки, канвас занимает свободную высоту,
   «Нужно»/«Сыграно» на канвасе больше нет. Подписи прогресса, темп и кнопки
   транспорта стоят в одну строку. «Счёт» показывает итог, тайминг, гистограмму
   и таблицу рекордов; воспроизведение при переключении не сбрасывается, урок и
   настройки сохраняются.
7. Настройки: повтор, такт счёта и его длина, число тактов, пропуск «Слушаю»
   на первых двух повторах, голос и его громкость, звук рисунка, его высота и
   громкость. Перезагрузка сохраняет значения и `cur`.
8. Режим игры: включить, выбрать вход, полоска уровня заходит за метку,
   калибровка (перед щелчками звучит счёт «раз, два, три, четыре»; после смены
   входа калибровка сбрасывается и просится заново), оценка попаданий, звёзды,
   статистика μ/σ, гистограмма; после счёта появляется «Погнали!», после
   уровня — попап «Удовлетворительно N%» (одна звезда), «Хорошо N%» (две),
   «Отлично N%» (три) или «Неудача N%» поверх канваса. Он гаснет сам, а в
   таблице рекордов появляется строка с точностью и звёздами. Первые два
   повтора после неудачи идут без «Слушай», дальше оно возвращается (можно
   выключить галочкой «Пропускать «Слушаю» первые 2 попытки»).
9. Тап по канвасу во время игры ловится как удар (на паузе — нет), то же делает
   клавиша `X`. Демо: кнопка «Демо» справа от строки темпа зажигается и
   приложение играет само, делая идеальные удары; рекорды в таблице не
   появляются; повторное нажатие снимает. Плей стоит строго в центре карточки.
10. Галочка «Подключить гитару» — единственное место, где спрашивается
    разрешение на микрофон; до неё игра идёт тапом и клавишей X. Если выход —
    динамики (ярлык вида «динамики/speaker»), микрофон не включается и
    показывается просьба надеть наушники; в наушниках или с неизвестным ярлыком
    вход включается как раньше.
11. Голос: в Network видны пять `voice/*.mp3`, статус «Точный голос загружен»;
   после офлайн-перезагрузки голос тоже загружается из кеша.
12. Офлайн: DevTools → Application → Service Worker зарегистрирован; после
    перезагрузки без сети приложение открывается. Проверить, что после изменения
    `index.html`, `style.css`, `app.js` или `voice/` поднят `VERSION` и новая
    версия подхватывается.

## Деплой

Пуш в ветку, из которой GitHub Pages публикует корень репозитория. Перед пушем:
поднять `VERSION` в `sw.js`, убедиться, что `.nojekyll` на месте, все пути
относительные. Remote в этом клоне не настроен.
